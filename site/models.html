MODEL RESOURCES

Reuse a complete model.
Keep its identity.

UniSEM combines neural prediction with an instance-generation workflow. A complete experiment therefore has more than one artifact. The model cards and artifact manifest record the available files, their identities, checksums, output semantics, and protocol limitations.

What belongs together?

ArtifactPurposeRequired context
Source checkpointFirst-stage reusable EM dense predictorEncoder, dense decoder, and cross-layer correction
Target checkpoint or adapterSecond-stage target specializationExact source checkpoint; LoRA configuration where applicable
Random forestMerge candidate fragments into instancesMatching 55-feature order, route, and preprocessing

An adapter alone is not a complete model. A random forest is paired with a specific prediction pipeline; it is not a substitute for neural weights. Historical decoder/HQ-only LightFT and the current all-block Q/V LoRA configuration must retain different identities.

The locally prepared target representatives use 625 labeled slices and seed 12345. The explorer also includes separate 160-slice checkpoints; their hashes are recorded in the viewer metadata. A 625-slice model is not the checkpoint behind the 160-slice examples.

Availability and checksums

Large model files are kept outside this static website. Read the cards for the actual local artifact locations and availability before running a command. The source archive does not silently download weights, load untrusted pickle artifacts, or replace a missing head with a random initialization.
